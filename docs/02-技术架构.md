# Kernel · 创意种子 — 技术架构方案

---

## 一、技术选型

### 结论表

| 层 | 选型 | 理由 |
|----|------|------|
| **前端框架** | **Next.js 15（App Router）+ TypeScript** | SSR 利于分享抓取与 SEO；一体化全栈省一套后端；Route Handlers 直接写 API |
| **样式** | **Tailwind CSS 4 + CSS Variables** | 与 DESIGN.md 的 token 一一映射，设计规范可直接落成 `@theme` |
| **组件库** | **shadcn/ui（Radix 底座）** | 无样式绑定、可完全按自家 DESIGN.md 改造，可访问性开箱即用 |
| **动效** | **Motion（Framer Motion）** | 卡片入场、票数跳动、榜单换位动画 |
| **数据请求** | **TanStack Query + Server Actions** | 乐观更新（点赞立刻变数字，失败回滚） |
| **后端** | Next.js Route Handlers（一期）→ 可拆 NestJS（规模化后） | 一期人力少，一体化最快；接口按 REST 规范写，拆分成本低 |
| **ORM** | **Prisma** | 类型安全、迁移方便 |
| **数据库** | **PostgreSQL 16** | JSONB 存配置、窗口函数算榜单、事务保证票据一致性 |
| **缓存/榜单/限流** | **Redis 7** | ZSET 天然适配排行榜；INCR 做限流；缓存热点作品 |
| **队列** | **BullMQ** | 截图、解压、生成海报、定时清理 |
| **对象存储** | **S3 兼容**（MinIO 自建 / 腾讯云 COS / 阿里 OSS） | 静态文件与生成图统一存储，CDN 直连 |
| **静态分发** | **Nginx + CDN**（泛域名证书） | 用户内容不经过 Node，源站零压力 |
| **截图/渲染** | **Playwright（Chromium）** | 封面自动截图 |
| **图片生成** | **Satori + @resvg/resvg-js** | 用 JSX 画海报，无需浏览器，速度快 10 倍 |
| **鉴权** | **Auth.js（NextAuth）+ 微信自定义 Provider** | 会话管理成熟 |
| **部署** | **Docker Compose**（一期）→ K8s（规模化） | 一台 4C8G 起步足够 |
| **监控** | Sentry（前端错误）+ Prometheus/Grafana 或 Uptime Kuma | — |

### 为什么不用纯 SPA + 独立后端？
分享链接需要被微信/飞书抓取 OG 信息，SPA 抓不到；且一期功能边界清晰，全栈一体化能省掉跨域、鉴权双写、部署两套的成本。等到 QPS 上千或团队分工细化，再把 `/api/*` 拆出去，前端代码不用动。

## 三、静态托管与安全隔离（最关键的一节）

用户上传任意 HTML 等于允许陌生人在你的域名上跑 JS。**隔离做不好，整个平台就是个 XSS 分发器。**

### 3.1 域名隔离（强制）

```
kernel.xxx.com          主站，有登录态 cookie
*.demo-sandbox.com     用户内容，泛域名，零 cookie
```

- 两个域名**必须是不同的注册域**（不能是 `demo.kernel.xxx.com`，否则 cookie 可以设到父域）
- 泛域名证书：`*.demo-sandbox.com`（Let's Encrypt DNS-01 / 云厂商证书）
- 沙箱域上永不下发任何 Set-Cookie

### 3.2 Nginx 配置要点

```nginx
server {
    listen 443 ssl http2;
    server_name ~^(?<slug>[a-zA-Z0-9_-]+)\.demo-sandbox\.com$;

    root /data/projects/$slug;
    index index.html;

    # 安全响应头
    add_header X-Content-Type-Options    "nosniff"          always;
    add_header Referrer-Policy           "no-referrer"      always;
    add_header Permissions-Policy        "camera=(), microphone=(), geolocation=(), payment=()" always;
    add_header Content-Security-Policy   "default-src 'self' data: blob: https:; script-src 'self' 'unsafe-inline' 'unsafe-eval' https:; frame-ancestors https://kernel.xxx.com; base-uri 'self'; form-action 'none'" always;
    add_header Cross-Origin-Opener-Policy "same-origin" always;

    # 禁止执行任何动态脚本
    location ~ \.(php|jsp|asp|aspx|cgi|py|rb)$ { return 403; }

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff2?|mp4|webp|avif)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # HTML 不缓存，方便更新即时生效
    location ~* \.html$ { add_header Cache-Control "no-cache, must-revalidate"; }

    # 项目不存在 / 已归档 → 交给主站渲染友好页
    error_page 403 404 410 = @fallback;
    location @fallback { proxy_pass https://kernel.xxx.com/_status/$slug; }
}
```

> `form-action 'none'` 是防钓鱼的关键：即使有人传了一个假登录页，表单也提交不出去。

### 3.3 详情页 iframe 预览

```html
<iframe
  src="https://k7Rm2xQz.demo-sandbox.com/"
  sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox allow-forms"
  referrerpolicy="no-referrer"
  loading="lazy"
  allow="fullscreen">
</iframe>
```
注意**不给** `allow-same-origin`——一旦给了，sandbox 形同虚设。

### 3.4 上传安全校验流水线

```
接收文件
  ├─ 大小校验            单文件 ≤ 100MB，ZIP 解压后 ≤ 200MB
  ├─ MIME + 魔数双校验    不信任扩展名
  ├─ ZIP 结构预扫描
  │    ├─ 条目数 ≤ 2000
  │    ├─ 解压比 ≤ 100:1        （防 ZIP 炸弹）
  │    ├─ 单条目 ≤ 50MB
  │    ├─ 路径穿越检测          （拒绝 ../、绝对路径、符号链接）
  │    └─ 扩展名白名单          html/css/js/json/图片/字体/音视频/文本
  ├─ 内容轻扫描（可选）    正则命中挖矿脚本 / 已知恶意域名 → 人工审核队列
  ├─ 落盘到临时目录 → 原子 rename 到 /data/projects/{slug}
  └─ 入队：生成封面截图 + 生成 OG 图
```

**扩展名白名单**：`html htm css js mjs json map txt md xml svg png jpg jpeg gif webp avif ico bmp woff woff2 ttf otf eot mp4 webm mp3 wav pdf csv wasm glb gltf`
命中白名单外的一律丢弃并在发布结果页列出被忽略的文件（透明告知，避免"我传了怎么不显示"）。

### 3.5 存储目录结构

```
/data/projects/
  ├── k7Rm2xQz/                  # slug 即目录名
  │   ├── index.html
  │   ├── assets/…
  │   └── .kernel/meta.json       # 入口文件、大小、文件数、上传时间
  └── p9Xn4Wct/
/data/covers/{slug}.webp
/data/og/{slug}.png
/data/tmp/{uploadId}/            # 上传中转，2 小时自动清理
```

## 四、性能与容量

| 项 | 设计目标 |
|----|---------|
| 首页 LCP | < 1.5s（图片 WebP/AVIF + CDN + 骨架屏） |
| 投票接口 P99 | < 120ms（Redis 先写，异步落库） |
| 排行榜查询 | < 20ms（Redis ZSET，不查库） |
| 单机承载 | 4C8G：约 200 QPS API + 静态全走 CDN |
| 存储估算 | 单作品均值 8MB × 5000 作品 ≈ 40GB；90 天回收后稳态约 20GB |

### 投票的并发一致性

高并发点赞不要直接 `UPDATE projects SET votes = votes + 1`（行锁热点）。

```
POST /api/votes
  1. 限流检查（Redis INCR + EXPIRE）
  2. SETNX vote:{projectId}:{userId} → 保证幂等，重复请求直接返回当前状态
  3. Redis ZINCRBY rank:campaign:{cid} 1 {projectId}   （榜单实时）
  4. Redis INCR votes:{projectId}                       （计数实时）
  5. 投递 BullMQ 任务 → 异步写入 votes 表 + vote_logs
  6. 立即返回新票数（前端乐观 UI 已经先动了）
```
数据库 `votes` 表上有 `UNIQUE(project_id, user_id)`，作为最终一致性的兜底。每 5 分钟一次对账任务，以 DB 为准校准 Redis。

## 五、部署方案

### docker-compose 服务清单

| 服务 | 镜像 | 说明 |
|------|------|------|
| `app` | 自建 Next.js | 主站 + API，2 副本 |
| `worker` | 自建 Node | BullMQ 消费者，含 Playwright |
| `postgres` | postgres:16-alpine | 数据卷持久化 + 每日 pg_dump |
| `redis` | redis:7-alpine | AOF 持久化 |
| `nginx` | nginx:alpine | 沙箱静态服务 + 主站反代 |
| `minio` | minio/minio | 对象存储（也可换云厂商 OSS） |

**环境变量清单**（`.env.example`）：
```
DATABASE_URL, REDIS_URL, S3_ENDPOINT, S3_BUCKET, S3_KEY, S3_SECRET
WECHAT_OPEN_APPID, WECHAT_OPEN_SECRET          # 开放平台扫码登录
WECHAT_MP_APPID, WECHAT_MP_SECRET, WECHAT_MP_TEMPLATE_ID  # 公众号授权 + 模板消息
SANDBOX_DOMAIN=demo-sandbox.com
SITE_URL=https://kernel.xxx.com
AUTH_SECRET, ADMIN_UNIONIDS
DEFAULT_TTL_DAYS=90
MAX_UPLOAD_MB=100
```

### 备份策略
- Postgres：每日全量 pg_dump + WAL 归档，保留 14 天
- 静态文件：对象存储开启版本控制 / 每周 rsync 到冷存储
- 演练：每季度做一次恢复演练

## 六、微信登录接入要点

| 场景 | 接口链路 |
|------|---------|
| **PC 扫码** | 开放平台网站应用 → `open.weixin.qq.com/connect/qrconnect` → 回调 code → `sns/oauth2/access_token` → 拿 openid + unionid |
| **微信内** | 公众号网页授权 → `open.weixin.qq.com/connect/oauth2/authorize`（scope=snsapi_userinfo）→ code → access_token → `sns/userinfo` |
| **打通** | 两端都要绑定到同一**微信开放平台账号**下，才有统一 unionid |

- 用户表主键关联 `unionid`（唯一索引），`openid_mp` / `openid_open` 各存一列
- 回调 URL 白名单需在微信后台配置，域名必须已备案
- **降级方案**：开发/测试环境或无微信资质时，走手机号验证码登录（同一套 user 表，`auth_provider` 字段区分）

## 七、可观测性

| 类型 | 方案 |
|------|------|
| 前端错误 | Sentry，含 SourceMap 上传 |
| 接口日志 | Pino 结构化日志 → 文件 / Loki |
| 业务指标 | 上传成功率、解压失败率、投票 QPS、清理任务耗时 → Prometheus |
| 告警 | 磁盘 > 80%、解压失败率 > 5%、异常投票尖峰 → 企微/飞书机器人 |
| 审计 | `audit_logs` 表，管理员所有写操作留痕 |
