# Kernel · 创意种子 — 静态作品发布与投票平台 · 产品方案

> 代号 **Kernel · 创意种子**：每一件杰作都始于一颗种子。把一个 zip 或一个 HTML 文件，变成一条可传播、可投票、可排行、会自动过期的链接。Slogan：Core. Code. Create. / 核心 · 代码 · 创造。

---

## 一、产品定位

| 维度 | 定义 |
|------|------|
| 一句话 | 面向活动 / 比赛 / 团队内部的**静态 Demo 托管 + 作品投票**平台 |
| 核心动作 | 上传 → 得链接 → 传播 → 被点赞 → 上榜 |
| 用户角色 | 创作者（上传者）、观众（投票者）、活动主办方、平台管理员 |
| 关键约束 | 只托管**纯静态**内容，无服务端逻辑执行；生命周期默认 90 天自动回收 |
| 差异点 | 托管平台（Vercel/Netlify）不做投票，投票平台（金数据/问卷）不做托管。Kernel 把两件事捏成一条链路 |

### 典型场景

1. **黑客松 / 设计周赛**：主办方建活动 → 选手传 zip → 生成链接 → 观众扫码投票 → 实时排行榜大屏
2. **团队内部评审**：多人各交一版原型，私密可见，内部投票选方案
3. **课程作业展示**：学生交单文件 HTML，公开广场浏览，学期末自动清理
4. **个人作品集临时分享**：仅链接模式，发给客户看，三个月自动失效不留尾巴

## 二、核心概念模型

```
Campaign（活动）
   └── Project（作品）  1 作品 = 1 短码 = 1 独立目录
          ├── Files（静态文件）
          ├── Tags（标签）
          ├── Votes（票 / 赞）
          └── Lifecycle（有效期 / 回收策略）
User（微信登录）── Vote ──> Project
```

**一句话规则**：**一个作品 = 一个文件夹 = 一串短码 = 一条链接。**

## 三、URL 与短码设计

| 用途 | 形态 | 说明 |
|------|------|------|
| 作品运行页（沙箱） | `https://{slug}.demo-sandbox.com/` | **独立沙箱域名**，与主站完全隔离，直出静态内容 |
| 作品运行页（备选） | `https://demo-sandbox.com/p/{slug}/` | 单域名方案，成本低但隔离性弱一档 |
| 作品详情/投票页 | `https://kernel.xxx.com/w/{slug}` | 带平台外壳：标题、作者、票数、活动标签、iframe 预览、投票按钮 |
| 直达源文件 | `https://{slug}.demo-sandbox.com/assets/x.png` | zip 内的相对路径原样保留 |
| 分享卡片图 | `https://kernel.xxx.com/og/{slug}.png` | 服务端生成的海报，带二维码 |

### 短码规则

- **字符集**：Base58（去掉 `0 O I l`），避免手抄误读
- **长度**：8 位（58^8 ≈ 1.28 × 10^14，碰撞概率可忽略）
- **生成**：`nanoid(alphabet, 8)`，写库唯一索引冲突则重试 3 次
- **自定义短码**：允许作者申请 3–32 位自定义（如 `hackathon-teamA`），走敏感词 + 保留词校验（`api / admin / www / static / og / p / w` 等保留）
- **示例**：`https://k7Rm2xQz.demo-sandbox.com/`

> **为什么用子域而不是路径？** 浏览器同源策略以域名为边界。子域方案下，作品 A 的脚本无法读取作品 B 的 localStorage / cookie，也无法向主站发同源请求。这是静态托管平台的安全底线。

## 四、功能模块

### 4.1 上传与发布

支持三种投稿方式：

| 模式 | 输入 | 处理 |
|------|------|------|
| **单文件** | 一个 `.html` | 重命名为 `index.html` 存入项目目录；内联资源不做拆分 |
| **ZIP 包** | 打包后的静态站点 | 解压 → 安全校验 → 定位入口文件 → 落盘 |
| **外链** | 一个外部 URL | 不落盘，详情页展示卡片，点击**新标签页跳转**（用户明确需求） |

**ZIP 入口文件识别顺序**：
1. 根目录 `index.html`
2. `dist/index.html`、`build/index.html`、`out/index.html`、`public/index.html`
3. 包内唯一的 `.html` 文件
4. 以上都不满足 → 弹出文件树让用户**手动指定入口**

**发布表单字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| 作品标题 | ✅ | ≤ 60 字 |
| 一句话简介 | — | ≤ 120 字，用于卡片和分享图 |
| 详细说明 | — | Markdown，展示在详情页 |
| 封面图 | — | 不传则**自动截图生成**（Playwright 无头浏览器抓首屏 1200×750） |
| 参赛活动 | — | 下拉选择进行中的 Campaign（这就是用户说的"注明参加哪场活动"） |
| 自由标签 | — | 最多 5 个，如 `AI` `可视化` `移动端` |
| 可见性 | ✅ | 公开 / 仅链接 / 私密 |
| 有效期 | ✅ | 默认 **90 天**，可选 7/30/90/180/365 天，永久需管理员授权 |
| 作者署名 | — | 默认取微信昵称，可覆盖为团队名 |

**上传体验**：拖拽区 + 分片上传 + 实时进度 + 解压进度 + 发布成功页（大号短链 + 一键复制 + 二维码 + 分享图下载）。

### 4.2 可见性与权限矩阵

| 可见性 | 广场可见 | 有链接可访问 | 可被投票 | 计入排行榜 |
|--------|:---:|:---:|:---:|:---:|
| **公开 Public** | ✅ | ✅ | ✅ | ✅ |
| **仅链接 Unlisted** | ❌ | ✅ | ✅（需活动允许） | ❌（默认） |
| **私密 Private** | ❌ | 仅作者/管理员 | ❌ | ❌ |

- 私密作品的沙箱访问需携带签名 token（`?k=<signed>`，有效期 24h，可续签）
- **管理员拥有全量查看权**，包括私密作品，但每次访问写入 `audit_logs`（可追溯，防止权限滥用）
- 作者可随时切换可见性；由公开转私密时，已产生的票**保留但冻结**，不计入榜单

### 4.3 投票 / 点赞

**基本规则**

- 必须**微信登录**后才能投票（这是主要的反刷手段）
- 一个用户对一个作品**最多 1 票**，可取消（取消后可再投，但记录 `vote_logs` 全量流水）
- **可以给自己的作品点赞**，也可以给别人的（按需求原文）
- 未登录用户点赞 → 弹出登录引导，登录后**自动补投**这一票（不丢失意图）

**活动级投票规则（Campaign 可配置）**

| 配置项 | 默认 | 说明 |
|--------|------|------|
| 每人总票数上限 | 不限 | 如设为 3，则该活动内最多投 3 个作品 |
| 允许自投 | 允许 | 主办方可关闭 |
| 投票时间窗 | 跟随活动周期 | 窗口外只读 |
| 结果公开时机 | 实时 | 可设为「截止后公布」，期间隐藏票数 |
| 评委加权 | 关闭 | 开启后评委票 ×N 权重 |

**防刷票策略（分层）**

1. **身份层**：微信 unionid 唯一约束；新注册账号 24h 内投票权重标记为"待观察"
2. **频率层**：Redis 限流，单用户 10 次/分钟、100 次/天；单 IP 60 次/分钟
3. **指纹层**：记录 IP、UA、设备指纹哈希，同指纹多账号集中投同一作品 → 风控标记
4. **行为层**：投票前需页面停留 ≥ 3 秒（前端埋点 + 服务端时间戳校验）
5. **审计层**：管理员后台可查看每张票的来源，支持**批量作废可疑票**，作废后榜单实时重算
6. **兜底**：开启「人机验证」开关（腾讯云验证码 / hCaptcha），高风险时段自动触发

### 4.4 活动（Campaign）与标签

**Campaign 字段**：名称、封面、简介、开始/结束时间、投票规则（见上）、报名开关、主办方、状态（草稿/进行中/已结束/已归档）

- 一个作品**可同时参加多个活动**（多对多），但每个活动内独立计票
- 活动有独立主页：`/c/{campaign-slug}`，含活动介绍 + 参赛作品墙 + 实时排行榜 + 大屏模式
- **大屏模式** `/c/{slug}/screen`：为线下活动准备的投影页，Top 10 实时滚动 + 票数动效 + 二维码

**Tag** 是轻量自由标签，用于广场筛选，与 Campaign 解耦。

### 4.5 排行榜

提供**两套榜单**，避免"早上传的永远第一"：

**① 活动榜（公平榜）** — 用于评奖，纯票数
```
rank = votes_valid DESC, first_vote_time ASC
```

**② 发现榜（热度榜）** — 用于广场推荐，带时间衰减
```
score = (V + 0.15·W + 0.02·U) / (T + 2)^1.4

V = 有效票数
W = 详情页停留 >10s 的深度浏览数
U = UV 独立访客
T = 发布至今小时数
```

**榜单维度**：日榜 / 周榜 / 总榜 / 活动榜 / 标签榜
**实现**：Redis ZSET 实时增量 + 每 5 分钟全量校准；前三名有专属视觉（金/银/铜渐变奖牌）

### 4.6 登录与账号

| 场景 | 方式 |
|------|------|
| PC 浏览器 | 微信开放平台**扫码登录**（网站应用 OAuth2） |
| 微信内打开 | 公众号**网页授权**静默/弹窗获取 openid + 昵称头像 |
| 兜底 | 手机号验证码登录（可选开启，应对无微信场景） |

- 用 **unionid** 打通同一主体下的公众号与开放平台账号
- 会话：HttpOnly + Secure + SameSite=Lax Cookie 存 session id，服务端 Redis 存会话；**沙箱域名下不下发任何 cookie**
- 首次登录自动建档：昵称、头像、unionid、openid、注册时间
- 用户中心：我的作品、我投过的票、我的活动、到期提醒设置

### 4.7 生命周期与自动清理（核心需求）

**状态机**

```
active（在线）
  └─ 到期 / 手动 ─→ archived（软删除，链接返回 410 + 恢复提示）
                        └─ 30 天后 ─→ purged（物理删除文件 + 保留元数据 90 天审计）
```

**过期策略**

| 项 | 规则 |
|----|------|
| 默认周期 | **90 天**（用户需求） |
| 可选周期 | 7 / 30 / 90 / 180 / 365 天 / 永久（永久需管理员审批） |
| 续期 | 作者在到期前可一键续期，重置计时；管理员可批量续期 |
| 提醒 | 到期前 **7 天 / 1 天** 通过微信模板消息 + 站内信提醒 |
| 宽限期 | 到期后进入 archived，保留 **30 天**可一键恢复 |
| 例外保护 | 获奖作品、票数 Top 10、被管理员置顶的作品 → **自动豁免过期** |
| 手动删除 | 作者可随时删除（进回收站）；管理员可强制立即物理删除（违规内容） |

**执行方式**：BullMQ 定时任务，每日 03:00 扫描 `expire_at < now()`；批量处理，单批 200 条，失败重试 3 次，结果写 `cleanup_logs`。

### 4.8 分享与图片生成（用户需求：生成图片介绍）

服务端生成三类图：

| 类型 | 尺寸 | 内容 | 技术 |
|------|------|------|------|
| **OG 卡片** | 1200×630 | 封面 + 标题 + 作者 + 活动标签 + 票数 | Satori + resvg（快，无浏览器） |
| **分享海报** | 1080×1440 | 封面大图 + 标题 + 简介 + 二维码 + 平台水印 | Satori + resvg |
| **作品封面** | 1200×750 | 作品首屏自动截图 | Playwright headless |
| **榜单战报** | 1080×1440 | 活动 Top 10 + 票数条形 + 二维码 | Satori |

- 生成后存对象存储，CDN 缓存，票数变化触发**惰性重生成**（票数每变化 10% 或超过 1 小时才重算）
- 详情页提供「保存海报」按钮，移动端长按可存图

### 4.9 后台管理

| 模块 | 能力 |
|------|------|
| **概览** | 作品数、今日新增、总票数、活跃用户、存储用量、即将过期数量、异常投票告警 |
| **作品管理** | 全量列表（含私密）、搜索/筛选、预览、改可见性、改有效期、置顶、下架、强制删除、批量操作 |
| **活动管理** | 建活动、配投票规则、审核参赛作品、导出成绩单（Excel）、大屏地址 |
| **用户管理** | 用户列表、封禁、设为评委、投票行为查询 |
| **投票审计** | 票据流水、按作品/用户/IP/指纹聚合、风控标记列表、批量作废、榜单重算 |
| **清理策略** | 默认周期设置、豁免规则、回收站、手动触发清理、清理日志 |
| **存储管理** | 各项目占用排行、大文件预警、总容量配额、孤儿文件扫描 |
| **系统设置** | 上传限额、允许的文件类型、CSP 策略、验证码开关、微信配置 |
| **审计日志** | 所有管理员操作留痕（谁、何时、对谁、做了什么、IP） |

## 六、边界与非目标

**明确不做**：
- ❌ 服务端渲染 / Node 运行时 / 数据库能力（纯静态，不是 PaaS）
- ❌ 自定义域名绑定（一期不做，二期可加）
- ❌ 版本管理与回滚（二期可加，一期覆盖式更新）
- ❌ 团队协作与多人编辑
- ❌ 支付与付费套餐（一期先跑通）

**已知风险与对策**：

| 风险 | 对策 |
|------|------|
| 用户上传恶意 HTML（钓鱼、挖矿、XSS） | 独立沙箱域名 + CSP + 举报入口 + 管理员一键下架 + 可选 ClamAV 扫描 |
| ZIP 炸弹 / 路径穿越 | 解压比 ≤ 100:1、文件数 ≤ 2000、单文件 ≤ 50MB、拒绝 `../` 与绝对路径 |
| 刷票 | 见 4.3 六层防护 |
| 存储无限增长 | 默认 90 天回收 + 单项目 200MB 配额 + 用量看板 |
| 大流量作品拖垮服务 | 静态内容全部走 CDN，源站只处理 API |

## 七、原型迭代已验证的产品决策

> 以下决策已在 `prototype/index.html` 高保真原型中经多轮用户红批确认，沉淀为产品级规范，供设计与开发直接沿用。

### 7.1 品牌与视觉

- **品牌名 Kernel · 创意种子**，Slogan：英文 `Core. Code. Create.` / 中文「核心 · 代码 · 创造」。Hero 中文标题「每一件杰作，都始于一颗种子」，其中"种子"用品牌渐变高亮。
- **品牌色仅三色梯度**：靛 `#4C5BD4` / 青 `#12B8B0` / 品红 `#E0489A`，构成固定品牌渐变 `linear-gradient(100deg,#4C5BD4,#12B8B0 48%,#E0489A)`。**早期方案的第四色 Amber `#F2A03D` 已废弃**。
- **渐变文字全站仅一处**：Hero 标题关键词"种子"（`background-clip:text`）。其余强调一律用纯色块 / 描边，不铺渐变。
- **平台是画框**：近白画布 + 1px 发丝边框，强调色单页面积 < 5%；氛围背景仅极低透明度三色径向渐变，置于 `z-index:-1`。

### 7.2 活动（Campaign）

- **活动即标签**：活动名称本身就是标签，参与者打 `#活动名` 即视为参与；**不单独建立标签体系**，作品详情 / 卡片不再展示独立标签 chips。广场与活动页的"标签筛选"指作品主题标签，与活动参与解耦。
- **活动广场**（`#view-campaign`）：标题「参加活动 · 让作品被看见」+ 简介，**无顶部 eyebrow、无阶段筛选器**；活动卡片自身含状态徽章（报名中 / 作品征集 / 投票中 / 已结束）即可区分。
- **活动详情 CTA 合并**：Hero 区 CTA 行始终显示「查看作品」，按阶段追加「前往报名 / 提交作品 / 去排行榜」，单行排列，避免按钮分散与信息重复。
- **详情状态提示框已移除**：原左下角 `.camp-phasebox` 提示（如"活动已结束 / 投票已关闭"）删除——阶段状态已由 Hero 状态徽章 + 阶段进度条承载。
- **创建表单**：删除「关联活动标签」输入；投票规则 chips / checkboxes 接上读写（`rules` 数组：限票档位 + 允许自投 / 评委加权 / 结果实时公开）。

### 7.3 作品与交互

- **作品卡片整体可点**进入详情（`data-goto="detail"` + `cursor:pointer`）；悬浮层仅保留「查看详情」视觉提示，**已移除「全屏运行」独立按钮**（原型验证：不需要脱离外壳的单独运行态）。卡片内投票按钮点击不触发卡片跳转。
- **作品详情**：浏览器框预览**去掉左侧竖线**，作品说明集中到右侧信息面板（置于有效期之后），避免信息重复。
- **排行榜**：前三名由数字序号替换为**奖杯 SVG**（金/银/铜背景渐变）；进入页面触发限时**烟花庆祝**（7 发 / 1.5s 自动停火）。「大屏模式」作为 feature teaser 保留；「导出成绩单」后端 API 保留（`/api/admin/campaigns/:id/export`），前端入口原型暂未展示，待活动管理页落地。
